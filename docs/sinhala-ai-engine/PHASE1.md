## New/extended API (Phase 1) — backend agent implements, frontend agents code against this

All under the existing JWT group, `{status,message,data}` envelope.

| Method | Path | Perm | Returns / body |
|---|---|---|---|
| GET | /engine/evaluations/{id} | engine.view | one evaluation: all columns, `metrics`/`baseline_metrics`/`subgroups`/`gate_result` decoded to objects, `release_approver_name`, `language_approver_name`, `created_by_name`, `training_job` {id,name} or null, `packages` [{id,package_id,version,state}] attached to it |
| GET | /engine/packages/{id} | engine.view | one package: all columns, `artifacts` decoded, `state_history` decoded (array of {from,to,at,by,by_name,reason}), `evaluation` summary {id,decision,task} or null, `allowed_next` (states reachable now per TRANSITIONS), `missing` {state: [evidence strings]} for each allowed_next that would be refused (computed by the same checks transition() uses, without changing anything), `bindings` [{task,profile,role:'active'|'previous'}] |
| POST | /engine/packages/{id}/artifacts | engine.manage | multipart: `file` (required), `path` (relative path inside the package; defaults to the file name). Allowed only in states candidate/quarantined. Server streams to writable/engine-artifacts/{package_id}/{path}, computes sha256 + size itself, replaces any artifact with the same path, revalidates paths with the existing safe-import rules (no traversal, no executables, no duplicates). Returns the updated package (same shape as GET). Each artifact gets `server_verified: true` when its hash was computed by the server. |
| DELETE | /engine/packages/{id}/artifacts?path=… | engine.manage | remove one artifact (candidate/quarantined only); deletes the stored file. |
| GET | /engine/approvals | engine.view | `{ evaluations: [{...summary, needs: ['release'|'language'...], can_approve: bool}], packages: [{...summary, needs: 'sign'|'activate'|'verify', can_act: bool}] }` — evaluations with decision pass/pending lacking an approval; packages in approved (needs sign → staged) or staged (needs activate). `can_*` already accounts for the user's permission and the "same person cannot give both approvals" rule. |
| GET | /engine/bindings | engine.view | `{ profiles: ['minimum','standard','apple','accelerated'], tasks: [...EngineGateService task keys], rows: [{task, profile, active: pkgSummary|null, previous: pkgSummary|null, updated_by_name, updated_at}] }` (a row per task×profile that has ever been bound) |
| PUT | /engine/bindings | engine.sign | `{task, profile, package_id}` — activate a staged/active package for that task+profile. Package must match the task and be signed (staged or active). Moves current active → previous. Package state becomes `active` if it was staged. A package that is no longer bound anywhere after the change is moved active→retired. Returns the bindings payload. 409 with reason when refused. |
| POST | /engine/bindings/rollback | engine.sign | `{task, profile}` — swap active and previous (previous must still be signed and not revoked). 409 when there is no previous. Returns the bindings payload. |

Keep the existing task-wide `/engine/packages/rollback` and `transition → active` working (they act on profile `standard`).
New migration `2026-10-24-000014_CreateEngineBindings`: table `engine_bindings` (id, task, profile, active_package_id INT null, previous_package_id INT null, updated_by INT null, updated_at), unique (task, profile); backfill `standard` rows from packages currently `active`. Permissions `engine.view/manage/sign` must exist in `permissions` and be granted to the admin role (check whether migration 000013 already seeds them; seed in 000014 if not, idempotently).
